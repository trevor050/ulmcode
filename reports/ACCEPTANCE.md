## Isolation and evidence method

Every run gets a fresh scratch state root containing its own config/data/state/cache/database/workspace and a pre-created `.ulmcode/operations` directory. Set the configuration suppression and explicit profile variables supported by the actual new host. Do not change `HOME`, run the profile installer against live directories, inherit auth environment overrides, or migrate an actual user store. Use synthetic credential-shaped sentinels and store only opaque handles outside the synthetic vault. Record non-secret path metadata and source checksums, never profile contents.

The target is `acceptance-scratch/lab.ts`, bound to `127.0.0.1` on an allocated port. The lab supplies a healthy inventory, an explicitly unvalidated candidate, malformed JSON, a transient 503 and bounded delayed response. Request traces contain method/path/time only. The lab is independent target infrastructure; all operation state and final deliverables must come from the real product.

Each case records start/end UTC, exact command argv or HTTP method/path and sanitized request body, rebuild HEAD, expected/actual behavior, exit/status codes, artifact paths/hashes and a categorical result: **accepted**, **failed**, **blocked**, or **unverified**. Tests do not print raw secret material to prove a leak; the scanner reports only file paths and counts. Preserve a negative case before any owner fixes it, then record a new run after the fix. Do not modify source artifacts to force a passing goal gate.

## Adversarial review criteria

The proposed operation contract in `OPERATIONS.md` cleanly separates store, execution adapter and deterministic engine. Acceptance will exercise the public host against the actual store across processes. The following details are essential to the implementation handoff:

1. Idempotency must bind payload content as well as a key. Returning an old result for a reused key with different scope/plan/command is a conflict, not successful suppression.
2. Durable launch intent must precede dispatch; recovery needs a stable adapter idempotency lookup when the launch receipt is lost. Unknown health must block duplicate execution.
3. Event append, revision and snapshot must have a crash-consistent source of truth. A JSONL append plus independent snapshot rename is not a single atomic transaction; demonstrate replay/reconciliation at the crash boundary.
4. Artifact containment must survive symlinks, missing-path races and cross-operation references. String-prefix checks alone do not establish containment.
5. Evidence claims and validated findings require separate proof states. A normalizer successfully parsing a candidate does not validate the security finding.
6. Final manifest/audit validity must bind the current operation, source revision or semantic content hashes, and ordering. A passing old audit is insufficient after source changes.
7. Goal review must be attached to actual session idle/continuation boundaries and persist review decisions. Calling a pure goal helper from a test is insufficient.
8. Profile/auth and operation-vault credentials are separate stores. Synthetic migration must preserve portable operation identity without exposing or silently copying incompatible OAuth material.
9. V2 public protocol changes require generated clients; UI, CLI and SDK must share host semantics. Independent frontend state cannot repair missing backend lifecycle behavior.
